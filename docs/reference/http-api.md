# HTTP API

Interactive documentation is served by a local backend at http://localhost:8000/docs (the hosted
one turns it off with `API_DOCS=0`). The same OpenAPI document is rendered below.

## Feature endpoints

| Path | Purpose |
|---|---|
| `POST /api/extract` | multipart `photos` (one to `MAX_PHOTOS` images, each at most `MAX_UPLOAD_MB`) and optional `crops` (label crops from `/api/segment`): reads the label into typed fields, each with `value`, `unit`, `confidence`, `source` (`photo`, or `label_crop` when crops were sent) and `raw`, plus `item_type`, `label_text`, `warnings`, the counts of photos and crops, the model used, `from_fixture`, `cost_usd` and `enhanced` (whether what the model read was contrast-stretched and sharpened; a blurred label adds a line to `warnings`) |
| `POST /api/segment` | multipart `photo` (one image) and optional repeated `concepts` (default `item`, `label`, `connector`; an unknown key is sent to the model as its own phrase): one region per match with `concept`, `box` (half-open pixels of the prepared photo), `confidence`, `coverage`, a JPEG `crop` data URL and the mask outline as `svg_path`; plus the `overlay` (the photo with the masks drawn over it), `warnings`, `width`, `height`, the model, `from_fixture` and `cost_usd` |

Errors, for both: `400` for a bad or oversized photo (by upload size or pixel count), a HEIC
file, too many photos or concepts, `422` when the required file field is missing, `502` when the model answer was incomplete or the Model API failed, `503` when the spend
cap is reached or fixture mode has no recorded answer. The `detail` text is safe to show.

## Inventory endpoints

JSON in, JSON out. An item carries its `fields` (the current value per field), every
`assertion` with its `provenance`, `confidence`, `source` and `review` state, the ids of its
separated `components`, and a `version` that every write increments.

| Path | Purpose |
|---|---|
| `POST /api/items` | save an item privately: `extraction` (an answer of `/api/extract`, every field becomes an observed value to confirm) and/or the item's own fields (`name`, `item_type`, `condition`, `faults`, `tests_done`, `accessories`, `location`, `notes`, `intent`, `availability`, `parent_id`); `201` with the item |
| `GET /api/items` | every item not deleted, newest first, without location and notes |
| `GET /api/items/{id}` | the item with its assertions and components |
| `PATCH /api/items/{id}` | change any of the item's own fields; with `version` set, a stale write is refused with `409` |
| `DELETE /api/items/{id}` | hide the item; `204`; its events stay readable |
| `POST /api/items/{id}/fields` | an owner value: `field`, `value`, `unit`, `provenance` (`owner_reported`, `documented`, `tested`, `estimated`); accepted as stated, beside any observation |
| `POST /api/items/{id}/assertions/{aid}/review` | `{"review": "accepted" \| "rejected" \| "proposed"}` for one observed value |
| `POST /api/items/{id}/components` | separate a part into its own item under this one; the parent's faults note it; `201` with the part |
| `GET /api/items/{id}/events` | the history: actor, time, change, version |
| `GET /api/items/{id}/photos` | how many photos are kept with the item (`count`); an item read from a capture has the capture's, an item saved from the web form the label photos it was read from |
| `GET /api/items/{id}/photos/{n}` | one of them as JPEG, `1` first, never cached; `404` past the count |
| `POST /api/items/{id}/public`, `POST /api/captures/{id}/public` | `{public}`: shown to the demo visitor (the item or capture, its values and photos, an item's drawn pictures; never a location, a note, a clip or a draft) or private again; the demo visitor's `GET` on items and captures lists the public ones and answers 404 for the rest |
| `POST /api/items/{id}/photos` | multipart `uploads`, one to `MAX_PHOTOS` in all on the item: re-encoded on the way in, metadata dropped; `201` with the new `count`; `422` over the limit, `400` for a file that is not an image |
| `POST /api/items/{id}/picture` | JSON `use` (a project template id, a use in your own words, or empty for the item itself): Muse Image draws what the item could become from its type, accepted values, condition and faults, one image per call, only on this request; `201` with the picture (`n`, `use`, `model`, `cost_usd`, `from_fixture`, `created_at`); `503` with *pictures are off on this server (PICTURE_ENABLED)* while the switch is off. Illustrative, never evidence; counted as a call that spends |
| `GET /api/items/{id}/pictures` | the pictures drawn for the item and whether this server draws any (`enabled`); the demo visitor sees those of a public item (404 for the rest) and is never let draw one |
| `GET /api/items/{id}/pictures/{n}` | one picture as JPEG, `1` first, never cached; `404` for a number never drawn. Kept beside the photos, never counted as one |
| `POST /api/items/{id}/scenarios/{scenarios_id}/reuse/{card}/picture` | Muse Image draws how a reuse card's project could look once built (`card` counts from 0), from the card's `title` and `what_it_does`, the item's kind with up to three accepted values (none that identify it, no price) and the card's `with_items` kinds; one image per call, only on this request; `201` with the picture (`use` is the card's title); `404` for scenarios of another item or a card that is not there; `503` while `PICTURE_ENABLED` is off. Kept with that set of cards and gone with the item; counted as a call that spends; refused to the demo visitor |
| `GET /api/items/{id}/scenarios/{scenarios_id}/reuse/{card}/pictures`, `GET .../pictures/{n}` | the pictures drawn for that card and `enabled`; one as JPEG, `1` first, never cached. Not for the demo visitor |

Errors: `404` for an unknown item or assertion, `409` on a version mismatch, `422` for a value
outside the allowed sets (intent, availability, provenance, review), a field name that is not
`snake_case`, a blank name, part name or value, an owner value claiming to be `observed`, a
`profile` that is not one that ships, or text
over its bound (names 200 characters, values 500, details and `*_notes` fields 4000). A key sent as `null` in a
`PATCH` means not given.

Nothing is stored |

| `GET /api/items/{id}/measurements/{mid}/photo` | the prepared JPEG the marks refer to |

Through the door: 429 over an allowance with `Retry-After`, 503 for a call that spends while `DEMO_PAUSED` is set. See [Demo access](../operations/demo-access.md) |
| `GET /api/profiles` | the shipped category profiles with their feature counts |
| `GET /api/profiles/{id}` | one profile |
| `GET /api/profiles/{id}/features` | the features worth measuring, each with `key`, `label`, `unit`, `tolerance_mm` and `how` |

| `POST /api/items/{id}/drafts` | JSON `mode` (`sell` or `give`), `holds_data`, `pickup`, `asking_price` (200 characters each, one line; the asking price one amount of dollars such as `$1,200.50`, else 422; the saved listing details are used when they are empty): one Muse Spark call (effort low) reads the item's accepted values (none that identifies it: a serial, MAC address or IMEI stays out, and one read off a photo is taken out of the text), the public listing details and the item's first four photos and writes a Facebook Marketplace (US) draft; the rules check `category` and `condition` against `backend/app/listing/marketplace_us.yaml`, set `price` in whole dollars and `price_basis` (the asking price, else the typical figure of the latest price guidance, named; `0` for a give-away), cut the `title` to 100 characters and the `tags` to 20, keep the `photos` order to the item's photos, append the disclosures (faults, what was and was not tested, what is included, data, pickup or shipping, availability), take out phone numbers, emails and street addresses, and drop any line that rests on nothing confirmed; the draft comes with `facts` (each naming its field), `uses` (give), `warnings`, `to_confirm`, `details_version`, its `checklist` (`prepare`, `photos`, and `data` when the item holds data), `ready`, `stale` and the `handoff_url`; 201. Counted as a call that spends |
| `GET /api/items/{id}/drafts`, `GET /api/drafts/{id}` | the drafts written for an item, each with `stale` set when the item changed since |
| `POST /api/drafts/{id}/checklist` | JSON `key` and `done`: tick or untick one step; 422 for an unknown step |
| `GET /api/marketplace/us` | the Marketplace (US) `categories` (each a `path`, whether it was `seen` on the public category pages, what it `holds`), the four `conditions` and the `free_category` |
| `GET /api/items/{id}/sell-details`, `PUT /api/items/{id}/sell-details` | the **Listing details** form: `condition_words`, `included` (`stand`, `cables`, `power_cord`, `box`, `manual`, `remote`), `included_other`, `faults`, `untested`, `data` (`none`, `wiped`, `not_wiped`), `reason` (private), `handover` (`pickup`, `shipping`, `either`), `area` (a city, ZIP or neighborhood), `asking_price` (above 0), `lowest_price` (private, not above the asking price), `availability`; each save is a new `version`; 422 for a street address in `area`, or a phone number, email or street address in the free text; `null` before the first save |
| `GET /api/drafts/{id}/photos.zip` | the item's photos in the draft's order (`01-photo-2.jpg`, ...), as stored: re-encoded on the way in, no metadata |
| `GET /api/items/{id}/marketplace`, `POST /api/items/{id}/marketplace/listed`, `.../sold`, `.../given` | what happened after the owner posted: `listed` (`on`, `price`, an optional `url` under `https://www.facebook.com/marketplace/`), `sold` (`on`, `price` above 0: also a reported sale for price guidance, and the item becomes `gone`), `given` (`on`; the item becomes `gone`); dates `YYYY-MM-DD`, not past the owner's day (UTC+14 at most); listed may follow listed, nothing follows `sold` or `given` (409), and a sale's event, reported sale and `gone` are one write; the `state` and the `events` |
| `POST /api/items/{id}/price` | JSON `currency` (ISO 4217, default `USD`), `country` (ISO 3166-1, optional), `city` (optional): Muse Spark searches for listings and sales of the same model, the rules keep only comparables a search result backs; four `quantities` (`asking`, `sold`, `reported`, `estimate`), each with `count`, `low`, `high`, `typical`, `basis`; the backed `comparables` with page and date, the `sources`, how many lines were `dropped`, three `strategies`, `weak` with its reason, `caveats`, `parts` when the item has components, `searches` made, and `stale` when the item changed since (a decision is no change); 201 |

Errors: `400` for a bad photo, `404` for an unknown item, measurement or profile, `422` for a
`request` that does not parse, a profile that does not exist, or a feature key that is not
`snake_case`.

| Path | Purpose |
|---|---|
| `GET /api/pair?origin=&api=`, `GET /api/pair.svg?origin=&api=` | what the phone needs to talk to this backend: the web origin given, or `api` when the backend has an origin of its own (a scheme, a host, an optional port, nothing more), and, when the demo is gated, a pairing as `token` with `expires_at` (a session of `PAIR_TOKEN_MINUTES`, at most 60, that claims the phone's code) for a browser through the door, or an empty `token` for the demo visitor and for a pairing, whose phone pairs as the demo visitor; as JSON or as a QR code, the image with `X-Pair-Expires-At` (the pairing's end, Unix seconds) and `X-Pair-Expires-In` (the seconds it has left by the server's clock, for a page whose own clock is off) when it carries one, both readable across origins; the access code never leaves the server and nothing is stored; 422 for an origin that is malformed or not one this server is reached at (the request's `Host`, a proxy's `X-Forwarded-Host` with the scheme in `X-Forwarded-Proto`, its `Origin` or `Referer` only when the browser marks it `Sec-Fetch-Site: same-origin`, or `CORS_ORIGINS`) |
| `POST /api/pair/code` | the phone's own access code, claimed with the pairing as the bearer token and shown once: `code`, `label` (`phone` and the first eight characters of the pairing's id), `expires_at` (`PAIR_CODE_DAYS`, never past the code that signed the page in); one claim per pairing; the code stands while that code does (revoked, expired, or a changed master code ends it); `gated: false` and no code without a gate; 429 once the address's code attempts are spent; 401 without a live pairing; a successful claim clears the address's count; 403 for a browser's session, a second claim, a phone's own code, when the code that paired the phone has ended, or when that code has `PAIR_CODE_MAX` phones with current codes already |
| `GET /healthz` | process is up |
| `GET /readyz` | config loaded, Model API mode (`live`, `record` or `fixture`; `fixture (key failed)` when the key did not answer the startup probe; `... for the code, recorded otherwise` behind a gate with a key), data directory writable, spend so far against the cap, `paused` once the cap is reached, and the gate under `demo`: `gated`, `live_models`, `paused` (the operator's switch), `daily_used`, `daily_cap`, `visitor_cap_per_hour` |
| `GET /api/version` | package version, the configured model IDs, the upload `limits` (`max_photos`, `max_upload_mb`, `max_clip_mb`) the web forms follow, and `pictures`, whether an item's picture may be drawn (`PICTURE_ENABLED`) |
| `GET /api/spend` | the spend ledger: total, cap, remaining, calls per model with token counts, live versus fixture calls |

Every response carries `X-Request-ID`. Send your own to have it echoed back and used in the logs
and in the spend ledger.
